# 한판 맞고 · ZLink Playground

컴퓨터와 치는 싱글 플레이 맞고(2인 고스톱) 웹 게임입니다. 이 싱글 게임을 [ZLink](https://zlink.systems)를 이용해 멀티 플레이 게임으로 개발하는 과정을 보여 주는 데모용 저장소입니다. 멀티 플레이를 붙이는 방법은 [멀티 플레이 붙이기](#멀티-플레이-붙이기)에 있습니다.

Vite, strict TypeScript, PixiJS v8(WebGL), GSAP로 만들었습니다. 효과음과 배경 음악은 Web Audio로 실시간 합성하므로 음원 파일이 없고, 외침은 브라우저 음성 합성(ko-KR)을 씁니다. 카드 그림은 Codex로 생성한 WebP입니다.

## 실행 방법

Node.js 22.12 이상을 권장합니다. 의존성은 정확한 버전과 package-lock.json으로 고정합니다.

```sh
npm ci
npm run dev
```

터미널에 표시된 로컬 주소를 엽니다. 휴대폰은 같은 네트워크에서 표시된 Network 주소로 가로 화면으로 접속합니다.

```sh
npm run build      # 타입 검사와 프로덕션 빌드
npm run preview    # dist 미리보기
npm test           # Vitest 단위 테스트, 감시 없이 실행
npm run typecheck  # strict 타입 검사
npm run lint       # ESLint flat config
npm run format     # Prettier
```

## 화면 흐름

타이틀에서 초급·중급·고급을 고르고 **게임 시작**을 누릅니다. 첫 판은 내가 선이고, 다음 판부터는 이긴 사람이 선입니다.

손패를 클릭하거나 숫자 키 1~0으로 냅니다. 먹을 수 있는 패는 빛나고, 마우스를 올리면 바닥에서 짝이 되는 패가 함께 빛납니다. 바닥에 같은 월이 종류가 다른 두 장이면 판이 어두워지고 두 장을 크게 보여 주며, 클릭이나 1·2로 고르고 빈 곳이나 Esc로 취소합니다. 손에 같은 월 세 장이 있으면 흔들기를 묻습니다.

7점 이상이 되면 고/스톱 창이 뜨고 지금 멈추면 받을 점수와 상대 점수(고박 위험)를 함께 보여 줍니다. 판이 끝나면 정산 화면에 점수 내역과 박·배수 도장, 가상 머니 변동이 나오고 **한 판 더**로 다음 판을 시작합니다. 설정에서 상대 실력, 게임 속도, 효과음·음악·음성, 월 숫자 표시, 화면 흔들림 줄이기를 바꿉니다.

규칙(기본값): 7점 나기, 손 10장·바닥 8장, 고(1고 +1, 2고 +2, 3고부터 ×2씩), 흔들기·폭탄 ×2, 피박(패자 피 7장 이하)·광박·멍박·고박 ×2, 나가리 다음 판 ×2, 쪽·따닥·싹쓸이·뻑 먹기·폭탄 피 1장(자뻑 2장), 첫뻑 피 1장, 삼뻑·총통 즉시 승리, 보너스피, 국진 자동 판정.

## 이벤트와 권한

화면 → `requestPlay(card, target?, shake?)` / `requestGoStop(go)` / `requestNextRound()` → 게이트웨이 → 이벤트 → `matchReducer` → 화면 순서입니다. 화면은 규칙 엔진이나 AI를 직접 부르지 않고, 결과를 미리 반영하지 않습니다. 패를 내도 `ActionResolved`가 오기 전에는 판이 바뀌지 않으며, 거절되면 `ActionRejected`가 옵니다.

| 이벤트           | 내용                                                                                                                             |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `RoundStarted`   | 판 번호, 나눠주기·바닥 보너스·총통 연출 이벤트, 그 뒤의 판 상태                                                                  |
| `ActionResolved` | 누가(0 = 나, 1 = 상대) 무엇을 했는지의 연출 이벤트(낸 패, 뒤집은 패, 먹은 패, 쪽·뻑·따닥, 점수, 고·스톱, 판 끝), 그 뒤의 판 상태 |
| `ActionRejected` | 거절 이유(`not-your-turn`, `illegal-action`, `round-over`, `round-in-progress`)                                                  |

맞고는 상대 손패와 더미 순서를 모르는 게임이라, 화면이 받는 판 상태(`TableView`)는 **보는 사람 기준으로 가린 상태**입니다. 내가 0번 자리이고, 상대 손패와 더미는 `hidden-`으로 시작하는 가린 카드로 장 수만 옵니다. 상대가 패를 내거나 더미에서 패가 뒤집힐 때 이벤트에 그 패가 처음 나타나고, 화면은 그 순간 뒷면 카드를 그 패로 바꿔 뒤집습니다. 가리는 규칙은 `model/view.ts`의 `toTableView`·`toViewerEvents`에 있고, 시험은 AI끼리 300판을 두며 두 사람 모두에게 상대 손패와 더미가 한 번도 새지 않는지 확인합니다.

로컬 게이트웨이(`LocalMatchGateway`)가 원본 판 상태, 규칙 판정, 컴퓨터의 수, 선과 나가리 배수를 소유합니다. 컴퓨터는 300ms 뒤 두고, 화면은 상대 행동을 연출하기 전에 생각하는 틈을 둡니다. `start` 이전에 구독하고, 화면을 벗어나면 `dispose`로 타이머와 리스너를 정리합니다. 앱 구성 지점은 `src/app/app.ts`입니다. 전적과 가상 머니(점당 100냥, 실제 돈이 아님)는 지금은 브라우저에 저장합니다.

## 멀티 플레이 붙이기

ZLink 시작 페이지에서 서버 템플릿을 받고, 이 저장소와 템플릿을 AI 코딩 에이전트에게 주어 멀티 플레이 게임을 만들게 합니다. 에이전트는 작업을 진행하면서 템플릿을 이미 받아 두었는지(받았다면 그 위치)와 서버 언어를 사용자에게 물어보고, 답에 맞춰 만듭니다.

### 1. 템플릿 받기

1. [zlink.systems/start](https://zlink.systems/start)를 엽니다.
2. 게임 장르에서 **보드**를 고릅니다. 서버 구조는 `board-tables`(Session node + Table node, Redis Location Store)입니다. 맞고처럼 테이블 하나에 두 사람이 앉아 차례로 두는 게임에 맞습니다.
3. 서버 언어를 고릅니다. 페이지에 나오는 언어(Node.js, Java 등) 가운데 원하는 것을 선택하면 그 언어의 템플릿을 받습니다.
4. 클라이언트는 **웹 브라우저**를 고릅니다. 브라우저 클라이언트는 TypeScript stream-connector(`@zlink-systems/stream-connector`)를 쓰며, 버전은 서버 템플릿에 고정된 Framework 버전과 같게 맞춥니다. 페이지의 설치·브라우저 가이드 링크를 함께 엽니다.
5. 서버 템플릿을 내려받아 압축을 풉니다(`my-game/`). 템플릿의 `README.md`와 `AGENTS.md`가 실행 방법과 확장 지점을 설명하고, `zlink.structure.json`의 `language`가 템플릿 언어입니다.

서버 실행에 필요한 도구(JDK, Docker 등)는 고른 언어의 템플릿 README에 적혀 있습니다. 클라이언트는 Node.js 22.12 이상이 필요합니다.

폴더는 다음처럼 두는 것을 권장합니다. 다른 곳에 받아 두었다면 에이전트가 물을 때 그 위치를 알려 주면 됩니다.

```text
work/
  zlink-matgo-demo/    이 저장소(클라이언트)
  my-game/             내려받은 board-tables 서버 템플릿
```

### 2. AI에게 줄 프롬프트

`work/`에서 AI 코딩 에이전트를 열고 아래 프롬프트를 그대로 줍니다.

```text
`zlink-matgo-demo/`는 컴퓨터와 치는 싱글 플레이 맞고(Vite + strict TypeScript + PixiJS)이고,
서버는 zlink.systems/start에서 받는 ZLink 보드 장르 서버 템플릿(board-tables)으로 만든다(이하 my-game/).
이 둘로 두 사람이 온라인에서 치는 멀티 플레이 맞고를 만들어 줘. 싱글 플레이(컴퓨터와 대국)는 지금처럼 동작해야 한다.

진행 중에 사용자에게 묻기(서버 코드를 고치기 전에 반드시)
1. 서버 템플릿: 먼저 "zlink.systems/start에서 서버 템플릿을 이미 받아 두셨나요?"라고 묻는다.
   - 받아 두었다면 압축을 푼 폴더 위치를 알려 달라고 하고, 그 폴더를 이후 my-game/ 자리에 쓴다(work/ 아래가 아니어도 된다).
     그 폴더의 zlink.structure.json에서 id(board-tables인지)와 language를 확인해 사용자에게 알려 준다.
   - 받아 두지 않았다면 zlink.systems/start에서 장르 "보드", 원하는 서버 언어, 클라이언트 "웹 브라우저"를 골라 받은 뒤
     압축을 푼 위치를 알려 달라고 안내하고 기다린다.
2. 서버 언어: 사용자에게 "서버 언어를 무엇으로 할까요?"라고 묻는다(zlink.systems/start에서 고를 수 있는 언어 중에서).
   받아 둔 템플릿이 있으면 그 언어를 함께 알려 준다. 답한 언어가 템플릿의 언어와 다르면 그 언어로 템플릿을 다시 받아 위치를
   알려 달라고 안내하고 기다린다. 템플릿을 직접 다른 언어로 옮겨 만들지 않는다.
3. 그 밖에도 진행 중에 정해야 할 것이 생기면(예: 템플릿에 없는 구조를 새로 둘지, 시간 초과 때 자동으로 칠지 질지) 추측하지 말고 사용자에게 묻는다.
아래에서 my-game/은 1번에서 정한 서버 템플릿 폴더를 뜻한다.

먼저 읽을 것
- my-game/README.md, my-game/AGENTS.md, my-game/zlink.structure.json: 노드 구성, 요청 흐름, 확장 지점, 실행·검증 명령.
  템플릿의 규칙(게임 상태를 소유하는 곳, Framework 콜백과 I/O를 두는 곳, 공유 메시지를 두는 곳, Session의 클라이언트 요청 허용 목록)을
  그대로 따른다. 허용 목록에 없는 패킷은 packet-not-allowed로 거절한다.
- zlink-matgo-demo/README.md, zlink-matgo-demo/AGENTS.md, src/features/matgo_game/gateway/match-gateway.ts, model/types.ts, model/view.ts:
  화면은 의도(requestPlay·requestGoStop·requestNextRound)만 보내고 게이트웨이 이벤트(RoundStarted·ActionResolved·ActionRejected)로만
  판을 바꾼다. 이벤트와 판 상태는 보는 사람 기준(0 = 나)이고 상대 손패와 더미는 가린 카드다.
- ZLink 공식 문서: https://docs.zlink.systems/llms.txt, 고른 언어의 서버 가이드, TypeScript stream-connector 브라우저 가이드.
  템플릿에 고정된 버전의 API만 쓴다.

서버(my-game/)
1. 게임 규칙: 템플릿의 기본 게임 규칙을 맞고로 바꾼다. 판정은 zlink-matgo-demo/src/features/matgo_game/model/의
   cards.ts·scoring.ts·engine.ts를 기준으로 한다(7점 나기, 고/스톱, 흔들기·폭탄, 쪽·뻑·따닥·싹쓸이, 피박·광박·멍박·고박, 나가리 배수,
   총통·삼뻑, 보너스피, 국진 자동 판정). 서버가 TypeScript면 그대로 가져와 쓰고(Pixi·DOM 의존성 추가 금지), 다른 언어면 같은 동작으로
   옮겨 상태와 분리된 순수 규칙으로 두며 engine.test.ts와 같은 경우(점수 계산, 특수 상황, AI끼리 수천 판 불변식)를 그 언어에서도 검증한다.
   TableState가 더미 순서, 두 사람의 손패, 바닥, 먹은 패, 고·흔들기·뻑 횟수, 차례, 선, 나가리 배수를 소유한다. 패 내기가 들어오면 서버가
   참가자·차례·손에 있는 패인지·고른 바닥 패가 같은 월인지·판 상태(고/스톱 대기 중인지)를 검증한 뒤 판정한다. 클라이언트가 보낸 결과는 믿지 않는다.
   더미는 서버의 암호학적 난수로 섞는다. 쓰지 않게 된 템플릿 게임 메시지·상수는 지운다.
2. 가림: 서버는 사람마다 따로 보낸다. 내 손패는 그대로, 상대 손패와 더미는 장 수만(가린 카드) 보내고, 상대가 낸 패와 더미에서 뒤집힌 패는
   그 순간의 이벤트로 처음 알린다. 상대가 보너스피로 더미에서 가져간 패는 상대에게만 알린다. model/view.ts의 toTableView·toViewerEvents와
   같은 규칙이며, view.test.ts처럼 "수천 판 동안 상대 손패와 더미가 한 번도 새지 않는다"를 서버 쪽에서도 시험한다.
3. 테이블: 한 Table Spot = 맞고 판 하나, 자리 2개. 두 자리가 차면 첫 판을 시작한다. 첫 판 선은 무작위, 다음 판부터 이긴 사람이 선,
   나가리면 선은 그대로이고 다음 판 점수 2배. 템플릿에 재배치(drain·relocation)가 있으면 스냅숏이 판 상태 전체(더미 순서, 남은 시간 포함)를 옮기게 한다.
4. 매칭: 템플릿은 JoinTableRequest로 이름 있는 테이블에 들어간다. 템플릿에 Matchmaker(FindMatch·CancelMatch)가 있으면 그것을 쓰고,
   없으면 대기열을 소유하는 ZLink Spot 하나를 둔다. 두 가지 입장을 지원한다.
   - 빠른 대전: 대기열에서 두 사람을 짝지어 새 tableId를 정하고 두 사람에게 알린다(상대 닉네임 포함). 대기열 소유는 한 곳만 둔다.
   - 방 코드: 한 사람이 방을 만들면 짧은 코드(6자리)를 받고, 다른 사람이 그 코드로 같은 tableId에 들어온다.
     코드 발급·조회·만료도 대기열과 같은 한 곳이 소유한다.
   대기 취소, 대기 중 연결 끊김(대기열·방 코드에서 뺌), 대기 만료를 처리한다.
5. 메시지(고른 언어의 공유 메시지 위치, 타입으로 정의): 빠른 대전 요청·취소, 방 만들기·코드로 입장, 매칭됨(tableId, 내 자리, 상대 이름),
   판 시작(판 번호, 나눠주기 연출, 보는 사람 기준 판 상태), 패 내기 요청(판 번호, card, target, shake), 고/스톱 요청, 행동 결과(누가, 연출 이벤트 목록,
   그 뒤 판 상태 — 이 저장소의 GameEvent와 같은 종류), 판 끝(승자, 이유: stop·chongtong·samppeok·nagari·timeout·leave, 정산 내역),
   다음 판 요청·응답, 상대 연결 상태, 거절(ActionRejected: reason·retryAfterMs — 템플릿의 JSON 계약 그대로).
   모든 판 이벤트에 판 번호와 순서 번호를 넣어 클라이언트가 중복·순서 어긋남을 버릴 수 있게 한다. 새 클라이언트 요청은 Session 허용 목록에 더한다.
6. 시간: 한 차례 20초(고/스톱 선택 포함). 시간이 지나면 서버가 대신 둔다(먹을 수 있는 패 중 가장 값진 패, 고/스톱이면 스톱).
   대신 둔 횟수가 한 판에 3번이면 그 사람이 진다(timeout). 시간 판정은 Table 한 곳에서 단조 시계로 하고, 시험용 시계는 Table 생성 때만 넘기며,
   남은 시간을 스냅숏(재배치 상태 포함)에 넣는다.
7. 가상 머니: 판 정산(점당 100냥)과 보유 머니, 전적은 서버가 계정별로 소유한다. 실제 돈·현금 표현은 쓰지 않는다.
8. 연결 끊김·재접속: 템플릿의 재접속(같은 Actor로 다시 바인딩, Rejoin 처리)을 그대로 쓴다. 끊긴 사람의 차례는 6번처럼 대신 두고,
   60초 안에 돌아오지 않으면 그 사람이 진다(leave). 돌아오면 지금 판 상태(보는 사람 기준)·차례·남은 시간을 한 번에 받는다.
9. 다음 판: 판이 끝나면 두 사람 모두 "한 판 더"를 누르면 같은 테이블에서 다음 판(판 번호 증가)을 시작한다. 한 사람이 나가면 남은 사람에게 알린다.
10. 시험: 템플릿의 기존 e2e 시나리오를 맞고에 맞게 고치고(zlink.structure.json의 scenarios 목록도 함께) 아래 시나리오를 더한다:
   빠른 대전 두 명 매칭, 방 코드 입장, 한 판 끝까지(고·스톱 포함), 차례가 아닌 패 내기·손에 없는 패·잘못 고른 바닥 패 거절(상태 그대로),
   상대 손패·더미가 응답에 없는지, 시간 초과 대신 두기와 패배, 재접속 뒤 같은 판 이어 치기, 나가리 뒤 2배 판, 다음 판.

클라이언트(zlink-matgo-demo/)
1. npm install @zlink-systems/stream-connector@<서버 템플릿의 Framework 버전>으로 버전을 정확히 고정해 설치한다.
2. OnlineMatchGateway(src/features/matgo_game/gateway/online-match-gateway.ts)를 MatchGateway 계약 그대로 구현한다.
   stream-connector로 서버(Session node의 ws:// 주소 — 서버 실행 때 "Server ready:" 줄 등에 나오는 실제 주소)에 연결하고,
   푸시 핸들러를 먼저 등록한 뒤 첫 패킷을 보낸다. 서버 메시지를 RoundStarted·ActionResolved·ActionRejected로 바꿔 구독자에게 보낸다.
   서버 자리 번호를 보는 사람 기준(0 = 나)으로 바꾼다. requestPlay·requestGoStop·requestNextRound는 요청만 보내고 판은 서버 결과를 받은 뒤에만 바꾼다
   (낙관적 반영 금지). 판 번호·순서 번호로 중복과 지난 판 이벤트를 버린다. dispose에서 구독과 연결을 닫는다.
   64비트 정수 필드는 JSON에서 10진 문자열로 올 수 있으니 숫자·문자열 둘 다 받아 바꿔 읽는다(템플릿 e2e 클라이언트를 참고).
3. 게이트웨이에 온라인 전용 기능(매칭, 다음 판 합의, 남은 시간, 상대 연결 상태)을 더할 때는 MatchGateway를 넓히지 말고 온라인 전용
   인터페이스를 따로 둔다. view/의 판 연출·카드·효과·HUD는 고치지 않고 그대로 쓴다(온라인 표시용 DOM 조각을 더하는 것은 된다).
4. 서버 주소는 Vite 환경 변수(VITE_ZLINK_STREAM_URL)로 받는다. 값이 없으면 타이틀의 온라인 대전 버튼을 비활성화하고 "서버 주소가 없습니다"를 보인다.
   기본 Session 설정이 루프백에서만 열리면, 휴대폰 등 다른 기기로 시험할 때 Session 설정의 stream 주소를 닿는 주소로 바꾼다.
   HTTPS 페이지에서는 wss:// 배포가 필요하다.

화면(지금 디자인과 같은 톤 — 녹색 담요, 원목 테두리, 금색은 버튼과 승리에만, 큰 글씨, 한국어)
1. 타이틀: "온라인 대전" 버튼을 더한다. 누르면 닉네임 입력(2~10자, 브라우저에 기억)과 세 가지 선택이 있는 창을 연다:
   "빠른 대전", "방 만들기", "코드로 입장"(6자리 입력칸).
2. 매칭 대기 화면: 펼친 광 다섯 장 위에 "상대를 찾는 중" 문구와 흐른 시간(초), "취소" 버튼.
   방 만들기면 큰 글씨로 방 코드와 "복사" 버튼, "친구가 이 코드로 들어오면 시작합니다" 안내.
3. 판 화면: 지금 화면 구성을 그대로 두고 왼쪽 점수판에 "나"/상대 닉네임, 차례인 쪽 강조와 남은 시간 막대(20초, 마지막 5초는 빨강과 째깍 소리).
   위쪽에 연결 상태 점(초록=연결, 노랑=다시 연결 중). 상대 차례에는 "상대 차례" 표시를 그대로 쓴다.
4. 상대 연결 끊김: 판 위에 반투명 띠로 "상대의 연결이 끊겼어요 — 60초 안에 돌아오지 않으면 승리합니다"와 카운트다운.
   내 연결이 끊기면 "다시 연결하는 중…"을 보이고, 실패하면 "타이틀로" 버튼.
5. 정산 화면: 지금 정산 창에 이유(스톱·총통·삼뻑·나가리·시간 초과·상대 나감)를 더하고 "한 판 더"(누르면 "상대의 답을 기다리는 중",
   상대가 먼저 누르면 "상대가 한 판 더 원해요"), "타이틀로". 상대가 나가면 한 판 더 버튼을 끄고 "상대가 나갔어요".
6. 휴대폰 가로 화면(844×390)에서도 겹치거나 잘리는 곳이 없게 한다. 세로에서는 지금처럼 가로로 돌리라는 안내를 보인다.
```

AI가 만든 결과는 위 완료 조건으로 확인합니다. 서버 언어가 무엇이든 더미와 손패, 규칙 판정은 서버가 소유하고, 클라이언트는 서버가 자기에게 보낸(가린) 이벤트만 그린다는 것이 이 데모의 핵심 구조입니다.

## 검증 범위

Vitest는 다음을 검증합니다.

- 점수 계산(광·열끗·띠·피, 고도리·홍단·청단·초단, 국진), 박과 배수, 쪽·뻑·따닥·폭탄·싹쓸이·자뻑 같은 특수 상황, AI끼리 3,000판을 두며 카드가 사라지거나 늘지 않는 불변식.
- 가림: 보는 사람 기준 자리 변환, AI끼리 300판 동안 상대 손패와 더미가 두 사람 모두에게 새지 않음.
- 이벤트 reducer.
- 로컬 게이트웨이: 차례·손에 없는 패 거절, 컴퓨터 응답 시각, 한 판 끝까지와 다음 판, 다시 시작·dispose의 타이머 정리.

화면은 데스크톱과 휴대폰 가로 배치, 터치·마우스·키보드 입력, 속도 설정과 흔들림 줄이기 설정을 지원합니다.

## 카드 그림 다시 만들기

생성 원본 PNG(1000×1600, 약 56MB)는 저장소에 넣지 않습니다. 다시 만들려면 Codex CLI로 생성한 뒤 WebP로 바꿉니다.

```sh
sh assets/cards/prompts/run.sh 1     # 1~4 배치, 결과는 assets/cards/originals/
python scripts/optimize-cards.py     # 512×820 WebP로 public/cards/ 에 저장
npm run manifest
```

그림이 없는 카드는 코드로 그린 그림(`src/features/matgo_game/view/card/painter.ts`)으로 대신 표시됩니다.
